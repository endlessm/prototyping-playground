# Systems

The Systems area: each design system's Overview, Libraries, Context and Skills, with the Theme, Assets and Components its navigation lists. The studio always has it (required), with a rail button (shapes icon) and a Home block. Systems themselves live in `src/systems/<key>/`, registered in `studio.config.json` (`tooling/systems/registry.ts`); there is no built-in "Studio" system: the studio's own interface is plain Nuxt UI.

- `module.ts` declares the module, its pages and its build data.
- `pages/index.vue` is `/systems`, the collection.
- `pages/system.vue` is `/systems/<system-id>`, the frame: the system's navigation (`components/SystemNav.vue`) in the section panel, kept on screen while its child pages change, each starting at the top. Its children are `overview.vue` (the address itself), `libraries.vue`, `context.vue` and `skills.vue` (the sections), `context-document.vue` and `skill-document.vue`, `theme.vue` (`/colors`, `/typography`, `/radius`, `/shadows`, `/spacing`, `/motion`, `/effects`, `/tokens`), `component.vue` (`/components/<slug>`, see Component pages) and `missing.vue` (anything else: "Page not found", with the navigation kept).
- `components/SystemsHome.vue` is the Home block: up to three active systems, the default first, and a link to the collection.
- `composables/useSystemCatalog.ts` loads the build data; `utils/pages.ts` holds the addresses and source files of a system's pages.

Addresses use the system's permanent `studioId`, so they survive renames: `/systems/<id>`, `/libraries`, `/context/<path>` (the file without `.md`), `/skills/<skill>/SKILL` and a skill's other documents (`/skills/<skill>/references/steps`) and text files, with their extension (`/skills/<skill>/scripts/check.mjs`), the theme pages, `/fonts`, `/icons`, `/images` and `/components/<folder>`. Tab titles read "<page> — <system> — Systems — <studio name>".

## Build data

The catalog (`tooling/systems/catalog.ts`) is computed on Node from each system's folder, refreshed in development when a file in the systems folder changes:

- `systems/catalog`: per system, its label, status, folder and colour modes; the Overview's `summary`, `guidance` and `code` (from `system.ts`'s `overview`); its libraries with the installed version (`null` when the package isn't installed); its theme tokens (custom properties in `app.stylesheet` and the local files it imports, each name once, by page: colours, typography, radius, shadows, spacing, motion, effects, other); components (see Component pages: each with its title, description, `source` note and `docs` link from its page's frontmatter, its files, and its examples with their preview IDs); local assets in `assets/` (fonts by extension, `icons/` as icons, other images as images); Context documents in file-tree order with their folders; and one entry per skill, with its files, `SKILL.md` first.
- `systems/components`: each component page's Markdown and examples text and its props, by `<system id>/<slug>`, loaded when a component page first opens (`componentPages`). Props are read from the component file with Vue's component metadata tooling (`tooling/systems/props.ts`, `vue-component-meta`); a file that can't be read is listed under the page's errors instead.
- `systems/documents`: the Markdown text of Context and Skills, and the text of skills' other files (a script), by repository path, loaded when a document first opens. Binary files (`tooling/systems/text-files.ts`: pictures, fonts, archives and the like by extension, or content with NUL bytes or invalid UTF-8) are left out.

The catalog also gives the system's own Overview content: an `overview.vue` in the system's folder, shown below the Overview's blocks. The dev server and the build add a system's component examples and its `overview.vue` to its preview document's views (`systemPreviews`), each under a fixed ID derived from the system, component and example (`tooling/systems/preview-ids.ts`), and watch the systems folder so open documents follow changes.

The deployed site gets active systems only: archived ones, with their documents, stay out of the build. The dev server and the build warn about a system's Context and Skills (`systemContentProblems`): Context holds Markdown documents; each skill is a folder with a `SKILL.md` whose frontmatter names it as its folder (lowercase words and single hyphens, at most 64 characters) and describes it (at most 1024 characters).

## The collection

"Systems", with "Components, styles, assets, and guidance for your prototypes." Each system is a card (name, summary or a generic line, "Used by N prototypes") or a list row, by the shared cards/list preference (`useCollectionView`, remembered in this browser as `design-studio:collection-view`, shared with other collections). The default system comes first with a **Default** badge, then the others alphabetically; archived systems sit in a muted **Archived** section below. The search ("Search systems", kept in `?q=`) matches the ID, folder, name, description and the word "Default"; no match shows "No matching systems" with **View all systems**.

Each card, row and navigation header has the system's "…" menu ("Actions for <Name>"): **Copy link**, and locally, for a registered contributor, **Copy path**. Archived systems have no menu until the lifecycle actions arrive (ticket 27: New system, rename, archive, restore, delete, default).

## A system

The navigation shows the system's name, its "…" menu and, for the configured default, "Default system". Its **Resources** toolbar has **Search** and **Expand all / Collapse all** (off while searching). Entries, in order: Overview, Libraries, Context, Skills, Theme, Assets, Components. Branches start open, fold with their chevrons, and stay as left for the session in this page (a reload opens them again); the branch holding the current page opens. Context keeps its folders; Skills shows one entry per skill. Theme lists only the pages its tokens fill ("No tokens yet" without any); Assets always lists Fonts, Icons and Images; Components lists documented components ("Empty folder" without any). Hovering a branch shows its folder, an item its file. Search ("Search system") filters by names and file paths, and Libraries by its libraries' names and descriptions, opening what matches; Escape clears it, a second Escape closes it; "No matching items." when nothing matches. Right-click a page for **Edit source** (locally, with its shortcut), **Copy link** and, locally, **Copy path**; pages are never renamed or deleted here.

- **Overview**: the name and summary (or "The guidance and code included in <Name>."), then three blocks. **Instructions**: Context documents and Skills, with the authored guidance or "No system instructions have been added yet.". **Toolkit**: Components, Theme tokens and Local assets, the authored code sentence and the colour modes. **Where it’s used**: active prototypes, the three newest (title and owner) and "View prototypes using this system" (`/prototypes?system=<id>`), or "No active prototypes use this system yet…". An archived system says so.
- **Libraries**: "The sources and tools behind <Name>.", each library as an entry with its anchor (`#<id>`), version ("v1.2.3", or "Not installed" with "Ask your agent to install this dependency."), description, links to the pages it supplies (Typography for fonts, Fonts, Icons, Images, and the components a package documents) and **Docs** in a new tab. A library declares those pages with `assets: ['fonts' | 'icons' | 'images']` and `components`.
- **Context** and **Skills**: the section itself says what it is for, "Select a file in navigation…" or "No files yet. Ask your agent to add useful material.", and that being listed doesn't load a file into a conversation. Documents read in the studio's own style (`components/SystemDocument.vue`): GitHub Markdown, the frontmatter's title when the document has no first heading, raw HTML shown as text, and relative links to the system's other documents, and to a skill's text files, opening in the studio. A skill's other text file (a script in its folder) opens read-only as its text under its path (`app/components/TextFileReader.vue`): locally in the source editor, highlighted; on the deployed site as plain monospace text. Binary files have no page ("Page not found"). Prototype documents get the shared renderer of ticket 16, which should replace this one.
- **Theme**: a page per token kind, listing the token names (ticket 25 adds live values, Assets and their pages). Until then those addresses are "Page not found" inside the system.
- **Overview content**: a system may add `overview.vue` to its folder; it renders below the blocks in the system's preview document, in the system's own look ("<Name>’s own overview").

## Component pages

A component is whatever files share a name in `components/`, in a folder of its own (`button/button.vue`, with `index.ts` re-exporting it) or flat (`IconButton.vue`); any one of them makes a page at `/components/<slug>` ("IconButton" → `icon-button`), listed under Components in the navigation (`tooling/systems/components.ts`):

- `<name>.vue`: the component. Its props table reads `defineProps`, its defaults and its doc comments.
- `<name>.md`: the page. Frontmatter `title` and `description` (required), `source` (a sentence on where it comes from) and `docs` (its documentation elsewhere); a `## When to use` section (required); anything else is optional.
- `<name>.examples.vue`: live examples. Each `<Example name="…">` (imported from `#studio/examples`) is one example, in the file's order, titled in sentence case ("WithIcon" → "With icon"). Write examples as screens write them.

The page reads, in order: the title and description; the Markdown page (the shared Markdown pipeline, its headings sized to the page's sections); **Examples**, each rendered alone in the system's preview document (`components/SystemPreview.vue`), in a frame as tall as its content, with **Show code** below showing the examples file highlighted; **Source**, with links to the libraries that list the component (`components` in a library, to its Libraries entry), the `source` sentence, **Component docs** and the file's path; then **Props**, closed at first and labelled "1 component · N props": Prop, Type and Default, required props marked "*", descriptions as tooltips on prop names, long types and defaults cut with the whole text on hover or focus, and "No props." or "Also accepts every native attribute of the element it renders." (unless the component sets `inheritAttrs: false`). Missing parts say which file to add ("No page yet. Add <name>.md…", "No examples yet. Add <name>.examples.vue…"). An example that throws shows "This example couldn’t render." with its error in its own frame; the other examples and the page still show. Files that can't load (a component whose props can't be read) are listed under "Some component files couldn’t load." with **Try again**. Pages follow their files on disk.

Documentation gaps (a component without a page or examples, a page without `title`, `description` or "When to use", an examples file without examples, two components with one address) are checked at dev start and in the build, as one warning per system listing the first five (`systemDocsReport`). A system's `docs` setting decides: `'warn'` warns, `'strict'` stops the build (and warns in dev), `'off'` stays silent.

`yarn component-docs <system> [component] [--yes]` (also `yarn studio component-docs`) adds the examples file and page a component is missing, or every component's, from templates (`tooling/systems/scaffold.ts`): a flat component first moves into a folder of its own with an `index.ts`, the first example fills required props (simple types with a value, others with `undefined` to replace), and files that exist are never touched. Without `--yes` it prints what it would do.

## Source mode

Locally, ⌘' / Ctrl+' (or `?mode=source`) switches a page to its source and back; ⌘S / Ctrl+S saves; **Done** returns; leaving with unsaved changes asks first. The Overview and Icons open `system.ts`, theme pages the stylesheet, documents themselves. A component page's source has tabs, **Page**, **Examples** and **Component** (when it has a component file), one file each (`components/ComponentEditor.vue`); a missing page or examples file says so with **Create files** ("Create the files this component is missing, from a template."), which runs the same scaffold. A skill's source has a file picker ("Skill source file") for its supporting files; files that aren't text say "This supporting file cannot be edited as text in Studio.". Switching files or tabs with unsaved changes asks first ("Discard your changes?": **Keep editing** / **Discard**). Source mode never renders the page, so a broken file can still be fixed. "Loading editor…" shows while the editor loads.

The dev server's file service reads and saves through `GET|PUT <base>_studio/files/system-source`, and creates a component's missing files with `POST` (`{ system, component }`), (`tooling/files/system-source.ts`), addressed by the system's permanent ID and a path inside its folder. Only `system.ts`, the stylesheet, files inside `components/`, Context documents and skills' files are reachable. Saving needs an Admin or one of the system's maintainers (`systemMaintainers`), an active system, and the version that was read (a change on disk since is a conflict). Others read, and the editor says why. The deployed site has no source mode, no file actions and no Copy path.
