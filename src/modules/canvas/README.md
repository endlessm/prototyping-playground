# Canvases

A page to arrange things on: views, documents and diagrams of its own prototype beside native Excalidraw text, shapes and arrows. It is [Excalidraw](https://github.com/excalidraw/excalidraw) 0.18.1 with the studio's menu, shortcuts and look. This module is optional: an Admin turns it off with `yarn studio disable canvas`, which keeps the files and lists them as unavailable, and nothing outside this folder imports it. Agent contract: [use-canvas](skills/use-canvas/SKILL.md).

Native Excalidraw tools are the authoring default, including text for annotations. The sticky notes in the Library are an example asset, not the standard annotation.

## The file

- **One file per canvas:** `<name>.excalidraw`, anywhere in a prototype: an Excalidraw scene as JSON. Its name in the navigation is the file name without the extension, with the canvas icon.
- **Identity:** a top-level `"studioId"` next to `"studioVersion"` (`types/canvas/identity.ts`). The dev server assigns it to a new canvas in your own prototype; `yarn studio identify <prototype folder> --yes` fills it in for files written by hand. A file that isn't valid JSON keeps its identity, so it still opens and says what is wrong.
- **Format** (`types/canvas/format.ts`, shared by the app, the build and the command line): Excalidraw's own scene (`"type": "excalidraw"`, `"version": 2`), so it still opens on excalidraw.com, kept slim and stable so canvases diff cleanly. No deleted elements, no images and an empty `files`; fields at Excalidraw's defaults and the volatile `updated` dropped (`version`, `versionNonce` and `index` stay: merging needs them); numbers rounded to 2 decimals, keys sorted, 2-space JSON with a trailing newline. Only the background and grid size of the app state are stored; the camera and the grid and snap toggles are personal. `studioVersion` is this studio's version of the shape (1): an unknown one is refused, a newer one opens read-only and is never saved over.
- **Links:** an item's `link` is its studio address, `/prototypes/<prototype-id>/artifacts/<artifact-id>` (a named state's address is its own ID), never a whole URL, so a canvas works on any host and under any base path. Excalidraw holds whole URLs: they are built on open (`withOrigin` in `island/Editor.ts`) and turned back into addresses on save (`storedLink` in `format.ts`); any other link is kept as it is. The address is made of permanent IDs, so a rename or move inside the prototype leaves it as it is; anything that repairs links reads and writes this form. A link to a file, relative to the canvas (an agent's, say), follows a rename or move as a new version of its element (`references.ts`; the prototypes README, "References follow renames and moves"); the change reaches an open canvas like any outside edit. A broken canvas is left as it is. In a duplicated prototype, a copied canvas's items link to the copied artifacts, also as new versions of their elements (the adapter's `copy`); the rest of the scene is copied as it was.
- **Check** (`types/canvas/check.ts`): the build stops on a canvas that isn't valid JSON, isn't one object, has no `elements` list, holds an image, has non-empty `files`, links to another prototype or has an unknown `studioVersion`, and each message says how to fix it. Only `/prototypes/<this prototype>/artifacts/…` links count as its own; the older contributor/prototype paths don't. A new canvas (`template`) is an empty scene with a white background.
- **Systems:** a canvas doesn't use its prototype's design system, so it never loads a preview document of its own.

## Opening

`components/CanvasPage.vue` is the artifact page; it keys `CanvasScene.vue` by the canvas's ID, so another canvas starts a fresh editor. The scene loads the editor's code, the file's text and whether you may edit it together before the editor mounts, so it never shows read-only first:

- **Locally**, the text comes from the dev server's file service, which also decides editing: your own prototype, or any as an Admin.
- **Deployed**, every canvas is bundled as the module's `files` build data (`types/canvas/bundle.ts`, by permanent ID) and opens read-only.

One quiet surface (`CanvasOpening.vue`) covers the scene. Screen readers hear "Opening canvas" at once; it shows after 200 ms as a text shimmer, static under reduced motion. The scene stays busy, inert and hidden until `useCanvasOpening` reveals it once with a 160 ms fade (none under reduced motion): after the opening camera has painted (a timer backs up animation frames in hidden tabs) and the live previews visible in the first view settle, never more than 2 s later. Previews report settling through `data-preview-state`, `data-diagram-state`, `data-artifact-phase` or `role="alert"` inside `[data-canvas-embed-id]` (`utils/opening.ts`). A file that can't be read shows "This canvas couldn't be opened" with the reason. An empty canvas shows no message, as in React (whose hint was painted under Excalidraw); the page reports it as `data-canvas-empty`.

The camera opens where you left it (this browser, `design-studio:canvas-camera:<canvas id>`, saved 400 ms after moving and on leaving), else fitted to the content at 90% of the space and never above 100% (`utils/camera.ts`). A damaged remembered camera is ignored.

## Saving and outside edits

Only locally, and only on a canvas you may edit (not a newer format). `utils/canvasFile.ts` is the framework-neutral logic; `composables/useCanvasFile.ts` connects it to the editor, the file service, toasts and leaving:

- **Edits save by themselves** through the same file service as the Source view (`PUT <base>_studio/files/source`), 1.2 s after the last change, or at least every 5 s during a long run of edits. Only a new scene version is an edit: selecting, panning, zooming and the scene Excalidraw hands back after loading never save, and identical text isn't rewritten. One save at a time; edits made meanwhile save next. Every save keeps the canvas's `studioId`.
- **Each save names the version it builds on.** If the file changed meanwhile (409 `changed`), the newer file is merged in and the union saved, up to 3 times; then saving pauses and a toast says "Couldn't save: the file keeps changing." until Retry. Other failures show one toast, "Couldn't save this canvas. Trying again.", and try again after 2 s, doubling up to 30 s. Both toasts offer Retry, as the status does, since they sit over it.
- **The save status** (`CanvasSaveStatus.vue`) at the bottom right says "Saved", "Saving…", "Unsaved changes" or "Couldn't save" with Retry, as a `role="status"`.
- **Leaving:** hiding the tab or leaving the canvas saves at once. Navigating inside the studio first tries to finish saving; if that fails, `CanvasLeaveModal.vue` offers Keep editing or Discard (`onBeforeRouteLeave` and `onBeforeRouteUpdate`). A reload or closing the tab while anything is unsaved shows the browser's leave warning.
- **Outside edits:** when the dev server says the file changed (`studio:source`, or a reconnect), the canvas reads it. Its own saves coming back are recognized and ignored, and a half-written or invalid file is skipped until the next change. With nothing unsaved the file replaces the scene; with unsaved edits both are merged (`utils/mergeRemote.ts`, with Excalidraw's own `reconcileElements`): per element the newer version wins, elements deleted in the file are removed, elements only here are kept and the union is written back. Either way the change comes in without a reload and outside the undo history.

## The editor island

Excalidraw is React. `island/mount.ts` mounts it in a React root of its own inside the Vue page, loaded on first use (so neither React nor Excalidraw is in the main bundle) and pre-bundled in development (`optimizeDeps` in `nuxt.config.ts`), so the first canvas doesn't make Vite reload the page. React and React DOM are used nowhere else. The island is plain TypeScript with `createElement`: Nuxt's JSX belongs to Vue.

| File                | What it does                                                                                                                                                                                                                            |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Editor.ts`         | Wires Excalidraw: the opening camera, the studio's colour mode (`theme`), Nunito for new text, read-only view mode, the library, wheel gestures over linked title bars, camera memory, scene changes for saving, and taking in the file |
| `Preview.ts`        | A canvas in a document: fitted, read-only, no UI ("In documents")                                                                                                                                                                       |
| `agent.ts`          | The tools in the open canvas, `window.__studioCanvas` ("Agent tools")                                                                                                                                                                   |
| `menu.ts`           | The trimmed menu (`UI_OPTIONS`, `CanvasMenu`): Undo, Redo, Toggle grid, Snap to objects, Help, Hide controls and the background swatches; read-only canvases keep only Hide controls                                                    |
| `shortcuts.ts`      | ⌘. / Ctrl+. hides the controls, ⌘⇧' / Ctrl+⇧' the grid, N a sticky note. ⌘' / Ctrl+' stays the studio's (the canvas's source)                                                                                                           |
| `stickyNotes.ts`    | The Library's four sticky notes and the note N adds                                                                                                                                                                                     |
| `helpDialog.ts`     | Hides the Help dialog's rows for shortcuts that don't work here                                                                                                                                                                         |
| `ControlTooltip.ts` | Fast tooltips with the shortcut keys                                                                                                                                                                                                    |
| `canvas.css`        | Excalidraw's UI in Nuxt UI's tokens (`--ui-primary`, `--ui-bg`, `--ui-border`, `--ui-radius`) in both modes, hidden pieces, and the narrow layout                                                                                       |

The canvas follows the studio's colour mode from the first paint and live (`useColorMode`); Excalidraw's own theme toggle is gone. Gestures: trackpad scrolling pans, ⌘/Ctrl + wheel and pinch zoom, and the canvas contains overscroll so a sideways swipe never goes back a page. Images are off three ways: no image tool, shortcut, paste or drop (`tools.image: false`), never stored, and refused by the build.

Excalidraw's fonts load from its CDN (esm.sh). Excalidraw's colour pickers call themselves dialogs, so the canvas marks itself `data-inline-dialogs` and the studio's shortcuts still work beside them.

## The Excalidraw patch

Yarn applies `.yarn/patches/@excalidraw-excalidraw-npm-0.18.1.patch` on install (the `patch:` protocol in `package.json`), to `dist/dev` and `dist/prod`:

- **Hide the link icon:** `renderLinkIcon` and `getElementLinkAtPosition` skip elements with `customData.hideLinkIcon`. Items on a canvas are embeddables whose `link` is their address; without this, Excalidraw paints a link icon on each, and its spot shows the raw URL and opens it.
- **Always the desktop layout:** `isMobileBreakpoint` returns false, so a canvas narrower than 730 px beside other panels keeps the desktop layout; `canvas.css` keeps its top row on one line (tools scroll sideways at 700 px, the Library button becomes an icon, tools shrink at 560 px).

Upgrading Excalidraw: `yarn patch @excalidraw/excalidraw`, make the same two changes in the printed folder, `yarn patch-commit -s <folder>`, then check that a canvas item shows no link icon and a narrow canvas keeps the desktop layout. Remove the patch when Excalidraw offers both.

## Items

An item is a stock Excalidraw `embeddable` whose `link` is an artifact's address, so Excalidraw owns paste, drop, selection, moving, resizing, copying and deleting. Only links to an artifact of this studio are items (`validateEmbeddable`, `itemAddress` in `format.ts`): a web page, a video or another site pasted or dropped on a canvas never becomes one, so a canvas never loads another site.

- **Placing:** drag a view, state, diagram or document row from the navigation onto the canvas (rows carry their permanent URL), or copy its link (Copy link) and paste it over the canvas. A new item is centered where it landed: 480 px wide, a 1440 × 900 screen plus its 36 px header if it shows live, else a one-row card (88 px). It has no Excalidraw outline, rounded corners or link icon (`customData.hideLinkIcon`, read by the patch). Placing and sizing are one undo step; items written into the file (an agent's) are sized outside the undo history (`normalizedItem` in `utils/embeds.ts`). A read-only canvas takes no drops.
- **What shows:** views, named states and diagrams of the canvas's own prototype show live, in the shared frame (`app/components/artifacts/EmbedFrame.vue`): a 36 px header with the title (a state reads "View · State") that opens the artifact in one click ("Open" on hover and focus); trackpad and wheel gestures over it still pan and zoom. A view is the preview document at 1440 px wide, scaled to the item's width and cropped at the bottom, so resizing changes the crop; a diagram is drawn whole, fitted. Documents, other canvases and types without a canvas preview (`embedIn` in the file type) show as cards with their icon, name, type and Open. A link to nothing is "Not found" (locally: moved or deleted, ask your agent to fix it; deployed: not on this site, it may be archived); a link into another prototype is "Another prototype" (copy the view here). A preview that crashes says "This preview could not render. Open the file to inspect it." without breaking the canvas and tries again when its file changes.
- **Pictures only:** the body of an item is inert and takes no pointer input, so clicks fall through to the canvas and select or move the item; only the header (or a card's Open) takes the pointer. A view's own styles stay in its preview document, so canvas link styles can't reach it.
- **The Vue side:** `renderEmbeddable` (`island/Editor.ts`) returns a thin, memoized React box per item (`data-canvas-embed-id`) and tells the Vue page about it; `CanvasScene.vue` renders `CanvasItem.vue` into each box through a `Teleport`, so items use the studio's router, i18n, manifest and colour mode. An item re-renders only when its own link, size or flags change, never on a pan or zoom frame. Removing an item unmounts its Vue render at once.
- **Live and offscreen** (`utils/embeds.ts`, `utils/liveViews.ts`): previews go live as they come near the view, at most one every 150 ms; before that they are sized placeholders. Items more than 400 px beyond the view aren't painted but keep running and updating. Zoomed out below 12% each preview shows its title in large type instead. About 30 previews stay live; every 3 s the least recently seen (not visible, not seen in the last 5 s) beyond that are unloaded, keeping their frame, and load fresh when they come back.
- **Following files:** links are permanent addresses, so a rename or move leaves items working; the title follows the manifest, and a view's or diagram's preview follows its source as it is saved.

## In documents

A canvas linked on its own line in a Markdown document (`![Board](./Board.excalidraw)`) shows as a fitted, read-only picture of the whole scene (`components/CanvasEmbed.vue`, the file type's `embed`). On another canvas it stays a card (`embedIn: ['document']`).

- **The same island:** `CanvasEmbedScene.vue` mounts `island/Preview.ts` through `mountPreview`, the same Excalidraw as the page in view and zen mode, with no toolbar, menu, saving, remembered camera or agent tools. The scene takes no pointer input, focus or keys; only the frame's title bar (Open) does. The camera fits the whole scene at 90% of the frame, never above 100%.
- **Items** are drawn as on the page (`composables/useCanvasItems.ts`, `CanvasItem.vue` through a `Teleport`), all live at once with no admission gate: the same previews, cards, Not found and titles.
- **Opening:** the same quiet surface, "Opening canvas" after 200 ms, one reveal and at most 2 s waiting for previews as the page. The 200 ms count from when the document's embed started: while the canvas code loads, the file type's `embedPending` (`CanvasEmbedPending.vue`, bundled with the studio, importing nothing heavy) shows the same surface. The frame keeps its size throughout.
- **Live:** it follows the colour mode, and in development its file (`studio:source`) without opening again; a document that embeds another canvas opens that one afresh. A canvas that can't load says "This canvas could not load. Open it to inspect its source."
- **Deployed:** the committed file, from the module's `files` build data, like the page.

## Agent tools

One set of tools, defined once in `tools/tools.ts` (pure: elements in, elements out; `tools/elements.ts` builds Excalidraw's element JSON, measures text from Nunito's character widths and routes arrows). Both ways of running them get the same arguments, results and `help`, and both resolve artifacts through `tools/context.ts`, built from the manifest:

- **On the file:** `yarn canvas <file.excalidraw> <tool> '<json>'` (`cli.ts`; arguments also from `--json-file <path>` or standard input with `-`, a leading byte-order mark ignored). It refuses anything but a canvas file inside a prototype, invalid JSON, no `elements` list or a newer format. Before a tool runs, every file of the prototype needs its identity: it names `yarn studio identify <folder> --yes`, and `--identify` runs that (reporting on stderr) and continues. A prototype the manifest leaves out (a system that isn't installed) is named with the reason. Changing tools need the prototype's owner or an Admin and an active prototype; `describe`, `artifacts` and `help` need no rights and never write. A write checks the file didn't change meanwhile ("The canvas changed. Read it again…"), keeps the canvas's identity and grid, writes the stable format and replaces the file atomically. The open canvas takes it in as an outside edit.
- **In the open canvas:** `window.__studioCanvas` (`island/agent.ts`, installed by `composables/useCanvasAgent.ts` while a canvas is open, in development only, never shipped to the deployed site). The tools run on the scene on screen; one call is one undo step, Excalidraw measures the text, new things scroll into view without zooming in, and edits save like the person's. It adds `context` (the file, whether it is editable, the selection, the viewport and what is on screen), `describe({ scope })` for `"selection"` and `"view"`, `point` (select and show, never zooming in), `screenshot` (a PNG data URL, scale 0.1–4, 40 px padding; items show as plain boxes) and `persist` (write now, waiting up to 5 s). On a read-only canvas the changing tools refuse; reading ones still work.

The tools: `describe` (each element's kind, place, size, text, colours, style, section, lock, arrow ends and artifact; sections and bounds; `ids` to limit it), `artifacts` (this prototype's artifacts by file, with title, type, preview or card and named states), `create` (up to 200 elements: `text`, `note`, `rectangle`, `ellipse`, `diamond`, `arrow`, `line`, `artifact`, `section`; placed by `x`/`y`, `below`, `rightOf` or `section`, else below everything; `@ref`s within a call; overlap and size warnings), `states` (every named state of a view side by side under its title, each linked to its state's address), `update`, `move`, `delete` and `help`. An `artifact` is a file of this prototype, with or without its extension, or a permanent address; it is stored as the address, and another prototype's is refused. Errors name the element, the field and what is allowed.

The [use-canvas](skills/use-canvas/SKILL.md) skill tells agents how to use them.

## The surface

The page offers tools drawn over it (such as comments) an [artifact surface](../../../app/utils/artifactSurface.ts) through `useArtifactSurfaceProvider`, read-only canvases included. It knows nothing about comments and works through the Excalidraw handle the agent tools use (`utils/canvasSurface.ts`, created in `CanvasScene.vue` once the editor is ready). It never changes the scene or the file; revealing a target moves only the camera.

- **Targets.** A point is over the topmost element whose box it is in (a line or an arrow within 6 px of its stroke; rotation counted), text written on a shape or an arrow counting as that shape or arrow, and over a section only when nothing else is there. Its anchor records `element`, the Excalidraw ID, `kind` (`item`, `note`, `shape`, `arrow`, `line`, `text`, `section`, `drawing`, `image` or `embed`), `text` (its own or its label's, whitespace squashed) and `at`, fractions of the element's own box before rotation. An item adds `item`, the address of the artifact it shows, and its `text` is that artifact's title. The label names the kind and the text, clipped to 40 characters: `Sticky note "Ask eng about the empty state"`, `Item "Board"`, `Rectangle`, `Arrow`, `Text "Review board"`. A sticky note is a rectangle with a note's fill and edge, as the agent tools tell them apart. Anywhere else is an empty spot, `{ kind: 'spot', label: 'Empty spot' }` with `point` in scene coordinates.
- **Finding a target again:** by element ID only, in the scene on screen, so an element moved by the person, by an agent's tool or by a change to the file keeps its comment, and a deleted one is "Target not found" until it comes back. A spot is always there.
- **Where things are.** Positions come from the scene and the camera (scroll and zoom) over Excalidraw's own box in the window. The surface listens to the handle's `onChange` and `onScrollChange` while a tool listens and tells it once, right after the update that draws the change, so pins follow panning, zooming and moved elements in the same frame, without sampling.
- **Revealing** an element scrolls it into view (`scrollToContent`, animated, keeping the zoom); a spot is centred.
- **Taking the pointer.** Capture listeners on the canvas's element stop every press, click, double-click, context menu and pointer move before Excalidraw or an item hears it, previews' frames stop taking the pointer and the cursor is a crosshair; Esc pressed while the canvas has focus goes to the tool, not Excalidraw. The wheel passes through, so trackpad scrolling still pans and ⌘/Ctrl + wheel and pinch still zoom. A two-finger pinch on a touch screen starts with a press, so it doesn't zoom in comment mode.
- **Room for the canvas's controls.** `bottomInset` (40 px) asks tools to sit above the save status and Excalidraw's footer.

## Remove it

Preview `yarn studio remove canvas` and apply it with `--yes`. Canvas files stay in prototypes. The `@excalidraw/excalidraw`, `react` and `react-dom` dependencies, the patch and the `optimizeDeps` entries need separate cleanup.
