# Lab

A bench for one system component at a time: the system's components in a list on the left and, for the open one, its title, description and tabs. It reads the Systems module's build data (`systems/catalog`, `systems/components`) and reuses its pieces, and owns no data: an app component's versions are views in prototypes, listed by the manifest. It works the same locally and on the deployed site, except that locally the Playground also makes versions of an app component and edits them as drafts, through its handler on the dev server (`server/versions.ts`) and the file service. It has a rail button (flask icon, after Systems), and no Home block, palette entries or skills.

## Addresses

Addresses use the system's permanent ID, as Systems does:

- `/lab` opens the default system's first component, or the first active system with components; it replaces itself in the history. Without any component it says "No components yet" with **View systems**.
- `/lab/<system id>` opens that system's first component the same way, or says it has none yet.
- `/lab/<system id>/<slug>` is the component's **Overview**; `/variants` and `/playground` follow it, and `/versions` for an app component. `/playground?version=<view id>` opens a version in the Playground, locally and on the deployed site.
- `/lab/<system id>/<slug>/versions/<view id>/changes` is a version's **Changes** (`changesAddress` in `utils/versions.ts`). It isn't a tab: the tab bar marks none, and its title reads "Changes — <component> — Lab — <studio name>".

The Lab offers active systems that have components (`labSystems`, the default first, then by name). An unknown or archived system, an unknown component, or an address under a component naming no tab shows "Page not found", with the component list kept and **View components** (to `/lab`) as the way back. Tab titles read "<tab> — <component> — Lab — <studio name>", and "Page not found — Lab — <studio name>" when nothing is there.

## The frame

- `pages/system.vue` is the frame: `components/LabComponentList.vue` in the section panel (`AppSectionNav`), kept on screen while the bench changes. Its header names the open system, or the **System** picker does when more than one active system has components; then **Search components** (title and address first, then description; Escape clears it; "No matching components.") and the system's components in the Systems navigation's order, the open one highlighted. Moving to another component keeps the open tab.
- The list has two groups. **App components** comes first: the components whose page names a copied app file in `app` (Studio sidebar) and every other `.vue` file in the system's app copy (`appComponents` in the catalog), each once, under its folder in the copy (App, Dashboard, Notifications…) by its own name: a page's title (Studio sidebar sits with the other App files) or, without a page, the name its path gives ("Hero" in Dashboard; a folder's `index.vue` is named for the folder). Hovering a name, and its accessible name, give the full one ("Dashboard / Hero"), and titles spell known acronyms in capitals ("SVG symbol"); `appPlace` and `labTitle` in `utils/lab.ts` work them out. **Components** follows, with the system's other components (for Endless Studios, its Nuxt UI wrappers) in the Systems navigation's order. Search covers both and keeps the groups. `labComponents` and `labGroups` in `utils/lab.ts` give the list, the bench and where `/lab` lands the same components.
- `pages/component.vue` is the bench: the component's title and description, then `components/LabTabBar.vue`, a set of links ("Component tabs", the current one `aria-current`), and the open tab beside them. It gives the tabs their component through `composables/useLabComponent.ts` (`provideLabComponent` / `useLabComponent`: the system, the component, its page data from `useComponentPages`, and `reload`).
- `utils/lab.ts` holds the addresses (`labAddress`), the tabs in order (`LAB_TABS`: id, i18n label, path), the tab an address shows (`tabAt`), the systems offered, where `/lab` lands and the list's search. The tab bar, the list and the titles all read `LAB_TABS`, so a new tab is one entry there and one child page in `module.ts`.

## Tabs

- **Overview** (`pages/overview.vue`), at the Systems page's reading width: **Open in Systems**, then the component's guide (`ComponentGuide`), Source (`ComponentSource`) and Props (`ComponentProps`), as its Systems page shows them, without the examples. Files that couldn't load are listed with **Try again** (`ComponentLoadErrors`). The Systems component page links back with **Open in Lab** while this module is on and the system is active.
- **An app component without a page** (`generic` in the catalog) opens like the others. Overview says it has no page yet and names the `app` field a page in the system's components would need (its copied file is never edited), then Source and Props, without **Open in Systems**, since Systems doesn't show it. Variants says the same before any examples. The Playground mounts the copied file alone in the system's preview document, its own props pre-populated by the usual rules, and locally shows its original, read-only. One that needs store state or query samples the system lacks renders what it can and reports the gap in the preview's console (`[Endless Studios] query … has no sample response`); a required prop only code can set blocks the stage and names it.
- **Variants** (`pages/variants.vue`): every example of the component's examples file in a grid, in the file's order, each a `components/LabVariantCard.vue`: its title as the Systems page writes it and its `SystemPreview`, so it renders alone in the system's preview document, fails alone and follows its file on disk locally. Two columns when the bench is at least 48rem wide (a container query, so hiding the component list counts), one below. An example that needs more room takes the row: `SystemPreview` emits `wide` when the example's content is wider than its frame or something in it stretches across it (a block button, a full-width table), and the card keeps the row from then on, so the grid doesn't flip as columns change. No new authoring. Under each preview, **Show code** opens that example's own code (its `<Example>` block, dedented, highlighted by the Markdown pipeline through `ComponentGuide`) and **Copy code** (named for its variant, "Copy code for Block", for screen readers) copies it with a toast, or says the browser blocked the clipboard and to copy from Show code; the snippets come in the component page data (`snippets`), with Unix line endings. The title, preview and code row of each card are rows of the grid (`grid-rows-subgrid`), so the cards of one row line up. A component without an examples file says which file to add, as its Systems page does.
- **Playground** (`pages/playground.vue`): the component file on the stage beside its dials, with Inspect above them both, and locally, for an app component, its app file's code beside the stage.
  - **The stage** (`components/LabPlaygroundStage.vue`) is the Systems module's `SystemPreviewFrame`: the system's preview document under the component's `playground` preview ID. New props arrive by message, so the component updates in place without reloading. The component sits centred on the stage. The stage grows with the component up to 70% of the window (40% on narrow screens), then scrolls inside. It stays in view while the dials scroll: beside them on wide screens, above them on narrow ones. When nothing in it takes any room, a note under it says it may need content only code can give. Props that make it throw show "This component couldn’t render." with the error until the next change.
  - **The dials** are [DialKit](https://www.npmjs.com/package/dialkit) (MIT; its vanilla build, inline, light) in `components/LabDialPanels.vue`. Its **Props** panel has one dial per prop, built by `utils/dials.ts` from the controls `utils/playground.ts` maps from each prop's metadata:
    - a union of string literals is a select (optional ones without a default offer **Default**, which leaves the prop unset; a required one without a value shows **Choose a value**);
    - `boolean` is an Off/On toggle;
    - `string` is a text field;
    - `number` is a text field read as a number (DialKit's only number dial is a ranged slider, and props declare no range);
    - anything else is listed under the panel in "Set in code", with its type (`components/LabPlaygroundCodeProps.vue`).
      DialKit labels a dial from its prop's name ("Model Value"). A help line under each dial gives the exact name, "Required" and the prop's description, and the dial's control is described by it. The panel component tags each DialKit row with its path (`data-lab-dial="props:color"`), as DialKit rebuilds rows only for a new set of dials. It hides DialKit's own toolbar and versions.
  - **Starting values.** The Playground always opens pre-populated, so the component never starts empty. Each dial's start is, first, the literal attribute its component's tag has in the `Default` example (or the first example): `label="Save"`, a bare `loading`, `:size="2"`, kept only when it fits the dial. `tooling/systems/example-seeds.ts` reads these on Node, from the component's own tag rather than a wrapper around it (`UInput` inside a `UFormField`), and the component page data carries them (`seeds`). Computed bindings, events, directives, `class` and `style` are left out. Next comes the prop's literal default. Last, text that shows (`label`, `title`, `description`, `placeholder`, `text`, or any required text) and is still empty gets a sample from its name ("Label", "Model value"). That sample is a value for the component rather than studio copy, so it isn't translated. An overlay's `open` the example doesn't set starts on, since closed it shows nothing and its examples open it from a trigger the stage lacks; closing it puts `?open=false` in the address. Seeded starts reach the stage, and a value equal to its start never enters the address.
  - **The address.** Changed values live in the address, one query parameter each (`?color=neutral&loading=true`), replaced rather than pushed. DialKit only shows them: a dial's change goes through the same rules, and DialKit follows the address back. A seeded prop emptied or set to **Default** is kept as an empty parameter (`?title=`), so it stays out instead of springing back. Reading the address back drops unknown props and values that don't fit, and the address is rewritten without them.
  - **Reset** sits in the panel's header and clears the changed values, back to the seeded ones. It stays enabled, keeping the keyboard where it was, and says "Values reset" to screen readers. It is left out when no prop has a dial.
  - **The component's own changes.** A prop the component changes itself (a modal closed with Escape or its close button emits `update:open`) reaches the studio as the preview document's `update` message, and its dial follows. Escape in the stage brings the keyboard back to the dial last used, once any overlay in it has closed, so an overlay's focus trap never keeps it there.
  - **When it can't start.** A component without props says it has none to try. A component without a component file names the file to add. Props that can't be read say so, with **Try again**; a component file that doesn't compile is one case, and the build leaves its playground out. A required prop with no value blocks the stage and names the prop: it asks for a value, or says only code can set it, with the dials disabled.
  - **Highlight and Inspect.** The stage's document is on the studio's origin, so `composables/useStageInspector.ts` reaches into it directly, as the frame already does to measure it: listeners on its window and DOM reads, with nothing of the studio's loaded into it. `components/LabStageOverlay.vue` draws in the studio's page, over the frame and clipped to it, from the elements' boxes (`utils/boxes.ts`).
    - Hovering or focusing a dial shows what it changes, with a label such as "Props › label = Save". For a prop, that is the elements holding its text, else those that changed the last time it did, else the component's root elements.
    - **Inspect** is a switch, on by default. While it is on, hovering the stage shows a thin box, and a click selects an element instead of reaching the component: its pointer, mouse and click events stop first. The selection shows the element's margin (orange stripes), padding (Cornflower stripes) and box, labelled `<tag> classes · W×H` and announced to screen readers. The prop dials that change it, or its nearest ancestor that one changes, are outlined. The selection is kept as child indexes from the document's body, so it survives re-renders and hot updates. Escape or **Clear selection** clears it.
    - This works the same on the deployed site, read-only.
  - **The code** (`components/LabPlaygroundEditor.vue`, the studio's CodeMirror `SourceCode`) sits beside the stage, or under it below `xl`, for an **app component** only, locally and on the deployed site: a system component whose page names the copied app file it presents in its `app` field (Studio sidebar: `app: components/App/StudioSidebar.vue`, see `src/modules/systems/README.md`). Other components, such as the Nuxt UI wrappers, show no code, since their only file is the system's own catalog page around them; Inspect's hint then leaves the code out. A divider (`components/LabEditorDivider.vue`, a `separator`) sits between them: drag it, or use the arrow keys (±20px, Shift ±80px; Home and End). A double click resets it, and this browser remembers the width (`design-studio:lab-editor-width`).
    - **The original.** The editor shows the app file itself, as the component page data carries it (`original`: its text, its path in the app's repository and the copy's revision), read-only, with "This is the app’s original. Make a new version to change it." and the path and the revision it was copied at under it, as a short hash ("…, copied from the app at 4a50874"; `composables/useOriginalSource.ts`). Typing changes nothing, and no class dials show: the Selected element panel says class dials change a version, and on the deployed site that making one needs the studio running locally. The editor's header keeps one layout at every width: row 1 says what is open ("Original: StudioSidebar.vue", or "Version: <name> · by <author>" without the file's extension) and whether it is saved; row 2 holds the page's `actions` (New version, which reads "Creating" while it runs; or Save as my version, **Show original** and **Changes**), with **Discard** and **Save** together at its end. Ghost buttons there and on the Versions cards get the solid buttons' 2 px focus outline (`GHOST_FOCUS` in `utils/lab.ts`).
    - **New version.** Locally, for someone registered, the original's header offers **New version**. It copies the original into the person's own "<Component> versions" prototype ("Studio sidebar versions"), made with the component's system on their first version through the prototype creation service, as a view `Version <n>.vue` holding its permanent ID and a version marker, `<!-- @lab-version <system id> <component slug> <app revision> -->` (`tooling/systems/app-versions.ts`). The manifest reads the marker: each view holding one has `labVersion`, and the main manifest lists them all in `labVersions`, with the preview ID of each one's stage. `utils/versions.ts` looks versions up from it (a component's versions, one by its ID, its prototype and owner, an older revision) for every Lab page. The version then opens in the Playground at `/lab/<system id>/<slug>/playground?version=<view id>`, with **Show original** to go back. The deployed site and someone who isn't registered don't get New version; the dev server's handler refuses them too.
    - **A version on the stage.** The stage renders the version inside the original's frame: the system's component file, loaded under an address of its own for that version, where only its import of the original (`AppFile.specifier`, `~/components/App/StudioSidebar.vue`) resolves to the version (`tooling/preview/lab-versions.ts`). The rest of the app copy, the frame's sample user and layout fixes stay, so a new version renders exactly as the original does. The frame loads as a copy under the version's address, so an edit to the frame's file reloads each version's copy. The version comes through a small component that also hands it the props it declares from the ones the Playground sent, so the dials can reach props the frame doesn't know. The dials list the frame's props, then the version's own (read again from the version or its draft after each change).
    - **Editing a version.** `composables/useVersionDraft.ts` reads the view through the file service and keeps edits in a draft through the Lab's handler, in `.studio/drafts/lab-versions/<the view's path inside the prototypes folder>`, which only its stage renders: the same unsaved status, Save (⌘S, Ctrl+S), Discard and **Keep my changes** as below. Save writes through the file service's source route, so someone else's version is read-only with the file service's reason, and its handler refuses a draft for anyone who may not change the prototype. Class dials rewrite the version's draft. The editor shows the version without the studio's two marker lines (`splitStudioMarkers` in `tooling/systems/app-versions.ts`), so its line numbers match Changes; drafts and Save put them back as the file has them, and the handler and the file service's source route refuse a text that drops or changes them (the source route only for a file that already has a version marker). Renaming, moving or deleting a version, or its whole prototype, takes its draft along (`followDrafts` in `tooling/files/drafts-folder.ts`).
    - **The code's shape.** The editor and the page take a `PlaygroundCode` (`composables/playgroundCode.ts`): the original is one, read-only, and a version's draft (`useVersionDraft`) is another, so an editable draft can take the original's place with Save, Discard and the class dials below.
    - **Only the stage renders the draft.** A version's stage loads the version's draft while there is one, and switches when one appears or goes away (`tooling/preview/lab-versions.ts`). Examples, Variants and Systems keep the saved file. The draft's relative imports resolve from the version's folder, and the import guard checks it as the version's file. The system's `preview.css` names the versions' drafts folder with an `@source`, so Tailwind builds their classes. The build has no drafts.
    - With a draft, the editor's header says "Unsaved changes" or "All changes saved", and Save confirms with "Version saved". **Save** (or ⌘S, Ctrl+S elsewhere) writes the draft over the file, over the version read, then drops the draft. If the file changed on disk meanwhile, a bar offers **Keep my changes**. **Discard** asks first, then drops the draft and returns to the file.
    - **Jumping to code.** Inspect marks the selected element's whole block in the code (`utils/classDials.ts`, `findElementSource`): from its opening tag to its matching close or `/>`. The block is found by the longest static `class="…"` all of whose tokens are on the element, walking up its ancestors; a button or link is found by its icon (`i-x:name` in the page is `icon="i-x-name"` in source).
    - **Class dials.** When the code is an editable draft and the selected element has a class attribute of its own, a **Selected element** panel offers dials for its plain spacing (`m*`, `p*`, `gap*`, `space-*`), radius (`rounded*`) and size (`w-*`, `h-*`, `size-*`, `min-*`, `max-*`) classes: sliders on the spacing scale in steps of 0.5, or selects of keywords. Each rewrites its one token in that attribute in the draft. Hovering one shows the space it changes with its size, such as "Spacing › paddingX = px-3 · 12px". Tokens behind a variant (`md:`, `hover:`), arbitrary values and `:class` bindings are left to code.

- **Versions** (`pages/versions.vue`), only for an app component (`LAB_TABS` marks it `app`, and the tab bar leaves it out for the rest): everyone's versions of the component, from the manifest (`versionsOf`), two columns when the bench is wide. Each is a `components/LabVersionCard.vue`: its name (the view's title), "By <owner>", locally when its file last changed (the handler's `dates`), "By you" for your own, **Read-only** for one you may not change, a preview of its stage (`SystemPreview` on its `stage` ID) and **Open in Playground** and **Changes**. The preview is a picture: inert, so Tab goes from the card's title to its menu, then Open in Playground and Changes, scaled down to fit 24rem (it only ever shrinks, so a component whose height follows its width can't make it flip), and opening the version when clicked. A version whose marker names another revision than the original's now says it was made from an older app and is compared with the current original (`olderRevision`); the Playground says the same over the version. Locally, someone registered gets **Save as my version** on someone else's version, here and in the Playground's editor header: the handler's `copy` writes it into their own versions under the same marker and opens it. Whoever may change a version (its owner or an Admin) has a menu with **Rename** (`components/LabVersionRenameModal.vue`, the file service's rename, which keeps the extension and repairs links), **Duplicate** (`copy` again, into their own versions) and **Delete** (the file tree's delete dialog, then the handler's `delete`, which moves the file to the computer's trash and takes the "<Component> versions" prototype along when that was its last version), plus **Open in Prototypes** for everyone. After Rename the keyboard returns to the card's menu button; after Delete it goes to the menu button of the card that took its place, or to **Open Playground** when none is left. The card tells the list before the delete's reply, since the manifest can drop the card first.
- **On the deployed site** the build ships each version's text beside the manifest, as it does for documents (`ManifestArtifact.text`), and `versionText` in `utils/versions.ts` reads it (locally it reads the file service). `?version=` opens the version read-only there (`useVersionCode` in `composables/useVersionText.ts`) with "Versions are read-only here. Run the studio locally to make your own.", and its dials are the frame's, since its own props are read only by the dev server. The original says "This is the app’s original. Run the studio locally to make a new version." there, and the Selected element panel "Class dials change a version. Run the studio locally to make a new version."
- **An app component without a page** gets versions too: its stage loads a frame of its own that renders only the original, and the swap gives that frame the version, with every prop falling through (`appComponents` and `genericFrame` in `tooling/preview/lab-versions.ts`). A copied file whose scoped styles `@reference` the app's stylesheet (`@reference "~/assets/css/main.css";`: Zero state, User profile, Program tile) gets versions like the rest: the import guard (`tooling/checks/imports.ts`) lets a view holding a version marker for its prototype's system `@reference` that system's stylesheet, or a file the stylesheet imports, as the app writes it through `~/`. Tailwind reads the file for its theme without emitting any of its CSS. Any other `@reference`, every `@import` and `:global`, and unscoped styles stay refused everywhere, a version included, with the guard's message.

## Changes

`pages/changes.vue` shows what a version changed in its app component, line by line, against the studio's copy of the original (`original.source` in the component page data), and names the file it compares with: its path in the app's repository and the copy's revision. A version made at another revision than the copy's now (`olderRevision`) carries a warning, since its changes then also undo what changed in the app since. The Playground's editor header links to it while a version is open, locally and on the deployed site (**Changes**, beside **Show original**), and so does each card of the Versions tab. The tab bar marks **Versions** as the current tab there.

- **Both texts are cleaned first.** The version loses the studio's two markers and any Windows line endings (`withoutStudioMarkers`); the original already comes with Unix line endings. So only real changes show, and only real changes leave the studio.
- **The diff** is `utils/changes.ts`, plain functions run in the browser: `changesBetween` (common ends trimmed, then a longest common subsequence of the lines left; removed lines before added ones in each run) groups the changes in hunks with three lines of context, as `git diff` does, and `components/LabChangesDiff.vue` shows them with both line numbers and a − or + mark.
- **Copy changes** copies `unifiedPatch`: a unified diff with `a/` and `b/` headers on the file's path in the app's repository (`original.appPath`, `frontend/app/components/App/StudioSidebar.vue`), so `git apply` takes it from the app repository's root. It marks a last line without a line break as Git does. **Download file** saves the whole cleaned version under the original's file name (`StudioSidebar.vue`).
- **A version's text** comes from `versionText` in `utils/versions.ts`, the one reader the Playground's deployed code (`useVersionCode`) and Changes (`useVersionText`, both in `composables/useVersionText.ts`) share. Locally: its draft when the Playground left one (what the stage shows, and the page says it includes changes not saved yet), otherwise its file, through the file service; nothing is written. On the deployed site: the file the build ships beside the manifest for the view (`ManifestArtifact.text` in its prototype's artifact list), as documents read theirs; without it the page says the file couldn't be read.
- The added and removed counts and the diff's marks use the success and error colours' 700 shades, which read at 4.5:1 or more on white and on the rows' tints.
- A version that doesn't exist, or belongs to another component, says so with **See all versions**; a component that isn't an app component has no versions to compare.

Interface text is under `lab` in `i18n/locales/en.json`.
