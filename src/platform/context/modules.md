---
title: Modules
description: Modules guidance for the Endless team.
---

All modules live in src/modules/<id>/. module.ts declares label, pages, rail, Home, palette data, file types, build data, preferences, handlers on the local dev server (server) and agent skill routes. tooling/modules/contract.ts is authoritative. studio.config.json determines activation; required modules remain enabled.

Use yarn studio list, enable, disable, remove and create-module. Commands that preview require --yes to apply; enable and disable apply immediately. Removal keeps content unless explicitly requested. Restart the recorded dev server after changing availability. Installed module code is trusted executable code.

Skills use module-relative paths and when triggers. Run yarn studio sync after changes. Disabling removes routes, adapters and application contributions without deleting files. Keep public prototype imports within the module's library (the library field, imported as @module/<id>); consult tooling/modules/contract.ts and the checks owner before exposing a new entry point.

Modules declare references adapters for file moves and renames; the registry retains them while a module is disabled so saved content can still be repaired. An adapter's optional copy rewrites a duplicated prototype's permanent IDs in a way its kind of source records (a canvas element's new version); without one they are replaced as text. Palette entries take hidden search keywords; paletteSource lists the manifest's prototypes or systems, and paletteOrder places the module's group in the command palette. A module adds items to a prototype's menu with prototypeActions: a browser file, relative to the module, whose default export returns { label, icon?, onSelect } items for a prototype; they show only to whoever may change it. A module draws a tool over every artifact page with artifactTool: a .vue component, relative to the module, given the prototype, the artifact and the page's artifact surface (app/utils/artifactSurface.ts) or null; only the studio running locally has it, and it is hidden while the source is open. A file type's page offers its surface with useArtifactSurfaceProvider; a surface may set bottomInset, the room its page's own controls take along the bottom (a canvas's save status), which a tool keeps clear of. A file type names the surfaces its embed preview shows on with embedIn (document, canvas; both when left out) and shows as a card elsewhere; embedPending names a small .vue component, bundled with the studio and importing nothing heavy, shown while that preview loads. Follow tooling/modules/contract.ts and the owning module README when adding a file type.

A module keeps files in each prototype with prototypeFolder: { name, one, other }, a hidden folder (a dot, then lowercase letters, numbers and dashes, such as the comments module's .comments) and what one file in it is and what several are, in plain text. Write it out as literal strings in module.ts: the scope check reads it from Git, and the registry refuses a declaration it can't read. The platform reads every installed module's folder from the registry (prototypeFolders), turned off or not, so a disabled module's files stay on disk and are still handled: renaming, moving, archiving and restoring a prototype carry the folder; duplicating leaves it behind; deleting counts its files in the module's words, in yarn studio delete-prototype and the studio's Delete; and the scope check lets anyone registered commit to it in any prototype ([Contributor scope](contributor-scope.md)). Dot folders are already outside the manifest, the file tree and the identity audit, so nothing in it is an artifact. Platform code never names a module's folder.
