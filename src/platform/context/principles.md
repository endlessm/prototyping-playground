---
title: Endless Design Studio principles
description: Endless Design Studio principles guidance for the Endless team.
---

## Give people ownership

Keep prototypes, decisions and context in readable repository files. Preserve the team's work and explicit choices.

## Curate a useful starting point

Use a coherent Nuxt UI interface and the default assigned system so designers can start with their real product. Add options for concrete needs.

## Provide minimum sufficient guidance

Keep common actions clear and disclose deeper reference only when it affects the task. Put deterministic mechanics in commands.

## Build parts that compose

Connect views, states, documents, diagrams and canvases through permanent links. Keep modules and systems understandable and independently maintainable.

## Declare what the system provides

Write defaults explicitly. Discover files, then honor declarations for registration, activation, capabilities and system assignment. Missing required declarations are validation problems, not implied defaults.

## Let the human direct and the agent execute

The person sets intent and judges results. The agent implements, verifies and makes work reviewable, asking for unresolved decisions rather than inventing them.

## Make context part of the environment

Maintain product context and sample assumptions beside the work. Use the assigned system's audience and components.

## Keep team collaboration dependable

Resolve contributors, preserve scopes and make shared changes reviewable. Registration adds a person without replacing the team's configuration.

Apply these principles with [Personas](personas.md); explain real tradeoffs rather than using a principle as an automatic verdict.
