# Settings and configuration

`service.ts` owns the validation shared by the local Settings page and `yarn studio configure`. `settingsSnapshot(root, options)` reads fresh configuration, profiles, roles, installed modules and system declarations. It exposes an exact-source SHA256 revision. `planSettings(snapshot, changes)` validates without writing; `saveSettings(snapshot, changes, revision, recovery)` refuses non-Admins and conflicting revisions before changing the file. The optional recovery flag is for explicitly authorised CLI repository recovery only. The browser never accepts it.

Role arrays hold permanent contributor IDs, not folder keys. `admins` must contain at least one registered contributor. `systemMaintainers` patches should retain all other systems' entries. Required modules cannot be disabled. Default-system changes never change prototype metadata: existing prototypes already have explicit assignments.

`config-file.ts` parses strict JSON, rejecting comments and repeated keys with the filename, and edits changed source ranges while preserving unrelated text and key order. `studio.config.schema.json` provides editor completion; runtime checks also verify references to registered profiles, systems and installed modules.

The dev-only Vite endpoint `<base>_studio/settings` accepts same-origin GET and POST. GET returns configuration, revision, role, system/module choices and a server-instance token, without contributor profiles. POST accepts `{ revision, changes }`, returns 403 for role refusals, 409 for conflicts and 400 for invalid input. No settings endpoint exists in the static build.

Settings doesn't decide restarts. The restart trigger (`../restart/trigger.ts`, wired by `../restart/nuxt-module.ts`) watches the configuration file and each system's `system.ts`, added, changed or removed. It debounces them, waits while a system operation holds its marker, then sends `studio:restarting` before restarting the Nuxt child, leaving the parent server and port intact. When the files are back as the server found them it sends `studio:not-restarting` instead, and a tab waiting on that server finishes without reloading. The trigger also creates the server-instance token Settings returns. Each page names the server that served it in a `studio-instance` meta tag, and Nuxt's configuration module carries the same tag, so the application knows the server its code came from. Waiting pages ask the light check, `<base>_studio/server`, which answers same-origin GETs with the token alone, so a broken configuration file can't hide the new server. The browser's side is the restart handoff in `../restart/handoff.ts`, with the names the server, the browser and the tests share in `../restart/names.ts`: one head script resumes a pending handoff on every page load and covers the page; a page from the outgoing server, or one whose code still comes from it, keeps the cover and reloads once another server answers; the cover lifts, and "Settings saved" shows once, only on a page whose document and code both come from the new server. On Linux the outgoing server answers beside the new one until the new one is ready, which `tests/e2e/restart-handoff.test.ts` replays in a real browser without a dev server. On a page still waiting to leave the outgoing server, the fallback appears at 15 seconds, with a longer-wait message at 30 seconds. Reduced motion stops the spinner and fade. Settings only starts the handoff after a successful save, with "Settings saved" as its confirmation, shown as a plain notice. A system change is the same handoff's other kind (see `src/modules/systems/README.md`): the tab that asked shows only its screen, never Applying changes as well.

Diagrams is an optional prototype tool. Text files (read-only supporting files in system skills) are included with Systems; Settings explains that relationship rather than offering an independent text-module switch.

The optional Documentation module is labelled Manual in Settings. Turning it off removes Manual routes after restart; the studio-owned Context & Skills browser remains available.
